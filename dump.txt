Key Components:
1. MCP Client: A user-friendly Web UI for submitting issues.
   - Entry Point: `mcp_client/app.py`
   - Logic: `mcp_client/file_extractor.py` (File Parsing)
   - UI: `mcp_client/templates/` & `mcp_client/static/`

2. MCP Server: Exposes Core Logic as MCP Tools.
   - Entry Point: `mcp_server/server.py`
   - Resources: `mcp_server/resources/queues.py` (Intake Data)

3. Core Logic: Business rules and LLM orchestration.
   - Classification: `mcp_server/tools/classify.py`
   - Severity: `mcp_server/tools/severity.py`
   - Routing: `mcp_server/tools/routing.py`

4. Infrastructure:
   - LLM Clients: `mcp_server/llm/groq_client.py` & `gemini_client.py`
   - Configs: `configs/*.yaml` (Industry Rules)
   - Loader: `mcp_server/config_loader.py` & `adapters/`

Ans:

This project is an Intelligent Intake & Triage System that automatically processes customer complaints or issues. It works in two main ways: via a Web Interface (for end-users) or via an MCP Server (for AI agents).

Here is the detailed end-to-end flow of how data moves, which files are used, and what functions are called.

### SCENARIO 1: END-TO-END FLOW (WEB USER)
This is the most complete flow where a user uploads a file or types an issue.

#### 1. User Submits Issue
- File: `mcp_client/app.py`
- Function: `submit_intake()` (Route: `POST /submit`)
- Action: The user submits a form with text and optionally a PDF/text file.
- Data Flow: `Request` object -> `issue_text` variable.

#### 2. File Extraction (If file uploaded)
- File: `mcp_client/file_extractor.py`
- Function: `extract_text_from_file(content, filename)`
- Action: Detects file type. If PDF, uses `pypdf` to extract text. If text file, decodes it.
- Data Flow: Binary File Content -> (processed by library) -> Clean String (e.g., "My internet is down...").
- Return: This string is appended to the main `issue_text`.

#### 3. Core Processing - Step A: CLASSIFICATION
Now the Web App acts as a client and calls the internal library functions directly.
- File: `mcp_client/app.py` calls `process_with_mcp()`
- Calls: `mcp_server/tools/classify.py` -> `classify_intake()`
- Action:
    1. Load Config: Calls `config_loader.py` which uses `adapters/generic_yaml_adapter.py` to parse `configs/banking.yaml` (or others). This adapter converts the YAML rules into Python objects.
    2. LLM Call: Calls `llm/groq_client.py` (or `gemini`) -> `generate_completion()`.
    3. Prompt: Sends text + categories to LLM "Classify this text...".
- Data Flow: Raw Text -> JSON Classification Result indicating Category (e.g., `atm_issue`) and Confidence.

#### 4. Core Processing - Step B: SEVERITY SCORING
- File: `mcp_server/tools/severity.py`
- Function: `score_severity(text, category_id)`
- Action:
    1. Check Keywords: Scans text for urgent words (e.g., "blocked", "fraud") using `check_risk_flags()`.
    2. LLM Call: Asks LLM to rate severity 1-5 based on emotional tone and impact.
- Data Flow: Text + Category -> Severity Dict (Score: 4, Priority: "High").

#### 5. Core Processing - Step C: ROUTING
- File: `mcp_server/tools/routing.py`
- Function: `route_case(category, severity)`
- Action:
    1. Load Rules: Reads `configs/*.yaml` to find routing logic.
    2. Logic: IF `severity > 3` AND `category == 'atm_issue'`, THEN `Team = 'FraudResponse'`.
- Data Flow: Category + Severity -> Routing Dict (Assigned Team, SLA: 4 hours).

#### 6. Final Result Display
- File: `mcp_client/app.py`
- Function: `templates.TemplateResponse("result.html", ...)`
- Action: Renders the final HTML page showing the User where their ticket went.

---

### SCENARIO 2: MCP AGENT FLOW (AI AGENT)
Here, an AI Agent (like Claude Desktop) connects to the system.

#### 1. Server Startup
- File: `mcp_server/server.py`
- Function: `main()` -> `mcp.run()`
- Action: Starts a FastMCP server, exposing the tools (`classify_intake`, `score_severity`, `route_case`) over SSE (Server-Sent Events).

#### 2. Tool Execution
- File: `mcp_server/server.py`
- Decorator: `@mcp.tool()`
- Action: When Claude wants to classify something, it sends a JSON-RPC request to this server.
- Data Flow: The server receives the request, calls the SAME internal functions from `mcp_server/tools/*` as the web app did, and returns the result to Claude.

### SUMMARY OF KEY FILES & ROLES
- `app.py`: The receptionist. Takes inputs, coordinates the work, shows results.
- `server.py`: The API gateway. Lets robots (agents) talk to the system.
- `tools/*.py`: The workers. Each does one specific job (Classify, Weigh/Score, Route).
- `config_loader.py` & `adapters/generic_yaml_adapter.py`: The rulebook keeper. The loader asks the adapter to read the YAML files, so everyone knows the rules.
- `llm/*.py`: The brain. Talk to external AI to "understand" the text.
